## 2. 优点

- **架构边界清晰**：Rust 管 IO，前端管 UI；IPC 集中在 `src/lib/ipc.ts`。
- **编辑器拆分克制**：load / autosave / unmount flush 行为基本保持；macOS 粘贴同时读 `files` 与 `items`。
- **图谱**：`from`/`to` 与 d3 的 `source`/`target` 分离；同步 tick 后停止；大库默认最大连通分量；Rust 有基础单测。
- **导出**：复用同一套 Tiptap 扩展；`renderTheme` 不污染主题缓存；HTML 导出前选路径 + `spawn_blocking`；图片内联有 20MB 上限与占位图。
- **资源清理**：读失败整库失败（避免误判空引用）；删除前重算引用；扫描 history / templates；有 grace window。
- **链接/排序**：heading fragment、session 持久化排序、history 迁移对齐 `.md` 路径，配套测试较多。

## 3. 问题

### P0（正确性 / 数据丢失）

1. **Quick Capture 事件载荷不匹配**（`quick_capture.rs` 发裸 `string`，`App.tsx` 读 `payload.text`）  
   结果：`undefined.trim()` 抛错；捕获窗已清空隐藏 → **输入静默丢失**。
2. **Inbox 打开时的 `appendReq` 可被重放并覆盖正文**（`tabs.ts` + `useNoteContent.ts`）  
   - 请求消费后仍留在 store；新 pane 的 `appliedAppendNonce` 从 0 起 → 旧 nonce 再执行。  
   - 若在磁盘内容加载前追加，可能把 Inbox 覆盖成单行（修 P0-1 后会从“坏功能”变成“丢数据”）。  
   - 另：editor 未就绪时已推进 nonce，导致该次捕获被吞掉。

### P2（建议）

- 图谱：滚轮以左上角缩放、无拖拽阈值、双向边双计、resize/主题不重绘、无障碍弱。
- 导出：PDF 窗过早显示、依赖 `afterprint`、代码块复制按钮入打印、嵌套 `.prose-note`、缺 Rust 单测。
- Pins：外删笔记残留；`loadPinned` 过滤后可能永久丢 pin；切 vault 未重置。
- 其它：同名笔记大小写 tab 分裂；`[[#标题]]` 行为怪异；关闭主窗 `exit(0)` 可能丢未 flush 编辑。

## 4. 建议修复（优先级）

1. **立刻**：对齐 quick-capture 载荷；消费并清空 `appendReq`；仅在内容已加载且 editor 就绪后追加。  
2. **导出**：剥 frontmatter；传 `noteAssetRoot`；job id + cancel；内联图片限制在 vault（且优先只改 `<img src>`）；富文本失败 toast。  
3. **安全/稳健**：history 命令走 `resolve_rel`；`hrefToRel` 安全解码；`link_graph` → async + `spawn_blocking`。  
4. **跟进**：统一链接解析；放宽资源引用扫描；图谱缩放/Worker；IME 防护。

## 5. 残余风险

- 大库图谱性能与 2000 阈值未经实测。  
- 链接规则分散在 graph / backlinks / noteLinks，后续易再漂移。  
- 隐藏打印窗在 macOS 上可能被节流。  
- 目录扫描跟随 symlink 有环风险。  
- 富文本剪贴板在真机 WebKit 上仍需验证。
